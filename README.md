# 自選股籌碼追蹤

只追蹤你在 `watchlist.txt` 填的股票。每個交易日盤後，GitHub Actions 會自動抓取公開資料（股價、法人、融資經 FinMind 取得；千張大戶來自集保結算所），計算三大法人、千張大戶與融資變化的分數，再更新到 GitHub Pages。

## 檔案結構

```
watchlist.txt                 ← 你的自選股（一行一檔）
index.html                    ← 網站頁面
scripts/fetch.py              ← 抓資料＋計分（只用 Python 標準函式庫）
.github/workflows/update.yml  ← 排程：台北 17:17、22:07（週一至週五）
data/latest.json              ← 最新結果（頁面讀這個）
data/report/YYYY-MM-DD.json   ← 每日結果（歷史清單）
data/all_stocks.json          ← 全市場股票清單（網頁搜尋用）
data/charts.json              ← 近 60 日 K 線、均線、法人（明細的 K 線圖）
data/fundamentals.json        ← 本益比、殖利率、淨值比、月營收、股利（每天抓一次）
data/debug.log                ← 最近一次執行紀錄（除錯用）
data/tdcc/                    ← 每週千張大戶資料
```

## 部署步驟

1. 在 GitHub 建立新的 repository（例如 `stock_watch`），把整個資料夾內容上傳到 `main` 分支（包含 `.github` 與 `.nojekyll` 這兩個隱藏項目）。
2. **Settings → Pages**，Source 選「Deploy from a branch」，分支選 `main`、資料夾選 `/ (root)`，儲存。
3. **Actions → 更新籌碼資料 → Run workflow**，手動執行第一次。大約 1 分鐘完成。
4. 完成後打開 `https://你的帳號.github.io/stock_watch/`。


## 如何看這個網站

這個網站看的是「**籌碼**」，也就是誰在買、誰在賣。它不會告訴你該買哪一檔，但能幫你判斷：手上或觀察中的股票，背後的資金是在進場還是退場。

### 每個欄位怎麼解讀

**三大法人（外資、投信、自營商）**

- **外資**資金最大，連續買超通常代表看好中長期，但也常因匯率或國際資金調度而大進大出。
- **投信**是國內基金，比較常集中買中小型股，**投信連買**往往是這個網站最值得注意的訊號之一。
- **自營商**多半是短線操作和避險，參考價值最低。
- **5 日累計**比單日數字重要。單日買超可能只是偶然，連續幾天累積才比較有意義。

**千張大戶持股比例**

- 持有超過 1,000 張的大股東所占的比例。**比例逐週上升**，代表籌碼往大戶集中；下降則代表大戶在分散出貨。
- 每週更新一次，看的是趨勢，不是單一週的變化。

**融資增減**

- 融資是散戶借錢買股。**融資減少、股價卻持平或上漲**，代表籌碼從散戶流向較穩定的買方，通常被視為健康。
- **融資大增**表示散戶追進，股價一旦回檔，容易出現斷頭賣壓。

**標籤**

- 「量增」「隔日沖賣壓」是警示用的：成交量突然放大或股價急漲，但法人沒有跟著買，隔天容易被倒貨。

### 實際可以怎麼用

1. **檢查持股的籌碼有沒有變壞**：例如法人從連買轉為連賣、大戶比例下滑、融資卻一直增加，這是「資金在撤、散戶在接」的組合，值得提高警覺，重新檢視持股理由。
2. **觀察名單的進場時機參考**：你本來就看好的股票，如果出現投信開始連買、融資減少、大戶增加，代表有人跟你看法一致，而且是比較有研究資源的人。
3. **看分數的「變化」，不是看絕對值**：某檔股票分數從 10 分連續幾天升到 50 分，比一直停在 50 分更值得注意。點開那一列，可以看到分數組成和近 10 日的明細。
4. **點開明細看近 10 日走勢**：例如目前的台積電，法人合計是賣超，但投信已經連買 10 天，代表外資和投信看法分歧，不能只看總數。

### 要知道的限制

- **籌碼是落後資訊**：盤後才公布，法人今天買不代表明天會漲，他們也會看錯、也會停損。
- **分數是固定規則算出來的**，沒有考慮基本面（營收、獲利）、產業前景、大盤環境和估值。高分不等於便宜，也不等於該買。
- **只追蹤你自己選的股票**，所以它不是選股工具，而是檢查你已經關注的標的。
- **大型權值股**（例如台積電）的法人進出常是被動式的資金調度（指數權重調整、ETF 申贖），訊號意義比中小型股弱。

比較穩健的用法，是把它當成**決策前的其中一道檢查**：先用基本面或你自己的理由決定要不要關注一檔股票，再用籌碼確認資金方向，最後一定要先想好停損點和部位大小。

我不是投資顧問，上面是籌碼指標的一般解讀方式，實際買賣還是要依照你自己的判斷和風險承受度。

## 網站功能一覽

- **大盤行情帶**：頁面上方顯示台股（加權、櫃買與幾個主要類股）和美股（道瓊、S&P 500、那斯達克、費城半導體）的最新收盤、漲跌與近 30 日走勢，資料存在 `data/market.json`。要換類股可修改 `scripts/fetch.py` 的 `MARKETS`。
- **盤中即時看板**（`realtime.html`）：最上方是台股大盤即時行情（加權、櫃買與主要類股，含當日走勢）；下方是開盤時間每 5～60 秒更新持股的最新價、今日損益、總損益、距停損多遠和當日分時走勢；跌破停損會標紅，也可開啟瀏覽器通知。可勾選同時顯示自選股。需要先架一個轉送站（見下方「盤中即時看板設定」）。
- **模擬投資**（`sim.html`）：用一筆虛擬資金（預設 100 萬，可調）假裝買賣任何台股，損益會扣掉手續費與證交稅，並和「同一天改買 0050」比較；可記錄買進理由、停損價和賣出心得，統計勝率與平均報酬。紀錄只存在瀏覽器，可匯出／匯入。設定了盤中即時看板的轉送站時會用即時價格，否則用最近收盤價。
- **Email 日報**：每個交易日晚上寄一封整理好的日報（持股損益與停損、今天新出現的警示、除權息、大盤），設定方式見下方「Email 日報」。
- **追蹤清單**：三大法人、千張大戶、融資、籌碼分數與 10 日走勢、本益比（含 5 年歷史位置）與營收年增率。
- **點開任一檔股票**，有四個分頁：
  - **K 線與法人**：近 60 日 K 線、5／20／60 日均線，下方對照三大法人買賣超；滑鼠移上去（手機用手指滑）可看每天的數字。
  - **籌碼分數**：分數走勢、分數組成、近 10 日明細。
  - **基本面**：本益比、殖利率、股價淨值比和過去 5 年相比貴不貴；股利紀錄；近 12 個月營收與年增率。
  - **我的持股**：輸入買進價、股數、停損價，自動計算損益與距離停損多遠。
- **我的持股總覽**：所有持股的成本、市值、損益，跌破停損會標紅提醒。持股資料**只存在你的瀏覽器**，不會上傳到 GitHub；換裝置可用「匯出／匯入」。
- **突破季線警示**：近 5 個交易日內，週線（MA5）或月線（MA20）由下往上穿過季線（MA60）的股票，會在頁面上方醒目列出，表格中也會標示；月線跌破季線也會提醒。K 線圖上會標出交叉位置。
- **除權息日曆**：自選股已公布的除息、除權日期、每股配發、殖利率、最晚持有日與發放日；有記錄持股會算出預計領到的股利。14 天內要除權息的股票，表格中會出現標籤。
- **匯出給 AI**：追蹤清單右上角的按鈕，把目前的清單整理成「分析指令＋資料表」，複製後可直接貼到 ChatGPT；也可以下載 CSV／Markdown，或勾選附上自己的持股（持股只會出現在這段文字裡，不會上傳）。
- **名詞小辭典**：欄位與標籤的白話說明，滑鼠移到欄位名稱或標籤上也會跳出說明。
- **回測報告**：籌碼分數的買進訊號與賣出警示，在過去兩年的實際效果。

## 盤中即時看板設定

證交所的即時報價不允許網頁直接讀取（沒有 CORS），GitHub Pages 又只能放靜態檔案，所以需要一個小小的轉送站。`proxy/` 資料夾裡有兩種，擇一即可：

- **Cloudflare Worker（免費，推薦）**：到 cloudflare.com 註冊 → Workers & Pages → 建立 Worker → Edit code，把 `proxy/cloudflare-worker.js` 整個貼上 → Deploy，複製 `https://xxx.workers.dev` 網址。免費方案每天 10 萬次請求，一個人用綽綽有餘。
- **自己的 PHP 主機**：把 `proxy/proxy.php` 上傳到支援 PHP 與 cURL 的主機。

轉送站程式有更新時（例如版本 2 開始支援大盤指數），要把新的程式重新貼上並部署一次，網址不會變。

接著打開盤中即時看板，按「⚙ 轉送站」貼上網址、按測試、儲存。網址只存在這台瀏覽器。轉送站只接受來自 `https://dorigo.github.io` 的呼叫，也只會轉送證交所報價與 Yahoo 分時線，不會經手你的持股資料；換了 GitHub 帳號要改程式開頭的 `ALLOW_ORIGINS`。

## Email 日報

每個交易日晚上（22:07 的排程，資料完整後）寄一封日報給你，內容有：持股損益與停損提醒、自選股「今天新出現」的警示與突破、7 天內的除權息，以及台股和美股的收盤。同一天只會寄一次。

**1. 準備寄件信箱（以 Gmail 為例）**
Google 帳戶 → 安全性 → 開啟「兩步驟驗證」→ 搜尋「應用程式密碼」→ 建立一組（名稱隨意），會得到 16 碼密碼。

**2. 在 GitHub 設定 Secrets**（repo 的 Settings → Secrets and variables → Actions → New repository secret）

| 名稱 | 內容 | 必填 |
|---|---|---|
| `MAIL_USER` | 寄件 Gmail 地址 | ✔ |
| `MAIL_PASS` | 上一步的 16 碼應用程式密碼 | ✔ |
| `MAIL_TO` | 收件信箱，多個用逗號分隔；不填就寄給 `MAIL_USER` | |
| `HOLDINGS` | 持股資料，網站會自動同步（見下方）；不設就不提醒停損 | |
| `MAIL_SERVER` / `MAIL_PORT` | 不用 Gmail 時填，預設 `smtp.gmail.com` / `465` | |

**3. 測試**：Actions → 「寄一封測試日報」→ Run workflow，約 30 秒後收信。

**持股自動同步**：把網站用的 GitHub 金鑰多開一個權限（github.com/settings/personal-access-tokens → 點金鑰 → Edit → Repository permissions → **Secrets** 設為 `Read and write`），之後在網站「我的持股」新增、修改、刪除，網站會自動加密並更新 `HOLDINGS`，持股區塊會顯示「✓ 已同步」。沒有這個權限時，「📧 同步到 Email 日報」會改成複製內容，讓你手動貼到 Secret。Secrets 不會出現在公開的 repo 裡，別人看不到。要停止寄信，刪除 `MAIL_PASS` 即可。

## 修改自選股

**網頁上修改（建議）**：點網站右上角「管理自選股」，可以用代號或名稱搜尋新增、點 × 移除，按「儲存並更新資料」後約 1～2 分鐘網站就會更新。
第一次使用需要貼一組 GitHub 金鑰（Fine-grained token，只勾選這個 repo，Contents 設為 Read and write），金鑰只存在你的瀏覽器中，不會上傳到任何地方。

**直接改檔案**：編輯 `watchlist.txt` 並 commit，Actions 也會自動重新抓資料。上市、上櫃、ETF 都可以填，系統會自動判斷市場。

## 調整計分

`scripts/fetch.py` 開頭的 `W_*`（權重）與 `FULL_*`（滿分門檻）可以自行修改；`NEED_DAYS` 控制保留幾個交易日。

## 常見問題

- **為什麼不直接抓證交所？** 證交所會擋國外 IP，GitHub Actions 的伺服器在美國，抓到的收盤行情是空的，所以改用 FinMind。
- **執行失敗**：打開 `data/debug.log` 查看每個請求的回應。FinMind 未註冊時每小時有請求上限，自選股很多（超過約 60 檔）時，可到 finmindtrade.com 免費註冊，把 token 加到 repo 的 Settings → Secrets and variables → Actions，名稱設為 `FINMIND_TOKEN`。
- **想馬上更新資料**：設定過金鑰的裝置，在網站「資料日期」下方會出現「↻ 立即更新資料」按鈕，按下後約 1～2 分鐘更新完成。適合排程延遲、失敗，或 16:00 後想提早看當天資料時使用。
- **傍晚顯示「部分資料尚未公布」**：融資餘額通常晚上才公布，22:07 的排程會補上。
- **千張大戶週增減是空的**：集保資料每週更新一次，需要累積兩週後才會有增減數字。
